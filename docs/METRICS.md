# Metrics

Every figure ORYN shows is computed from recorded runs, scenarios and requirements in
Postgres. Nothing is estimated, sampled or produced by a model. The source of truth is
[`crates/oryn-db/src/analytics.rs`](../crates/oryn-db/src/analytics.rs); this page and that
file change together.

## Terms

- **Job**: one attempt to run one scenario. A retry creates a new job and marks the
  previous one `superseded`.
- **Final attempt**: a job that is not superseded. Metrics count final attempts only,
  so a scenario that failed once and passed on retry counts once, as passed.
- **Window**: the last *N* days (`?days=`, default 30, capped at 365), applied to the
  job's `finished_at` (or the execution's `created_at` for execution counts).
- **Scope**: the projects the caller can see. Private projects without a grant never
  contribute.
- Cancelled jobs are excluded from every rate.

## Pass rate

<a id="pass-rate"></a>

```
pass_rate = passed / (passed + failed + errored)
```

over final attempts finished in the window, where `errored` counts `error` and
`timed_out`. It is `null` (shown as "–") when the denominator is 0. ORYN never shows a
pass rate it has no runs for.

## Failure rate

<a id="failure-rate"></a>

```
failure_rate = (failed + errored) / (passed + failed + errored)
```

Same population as the pass rate; `pass_rate + failure_rate = 1` whenever both exist.

## Mean duration

<a id="mean-duration"></a>

- **Mean scenario time**: arithmetic mean of `duration_ms` of final attempts finished
  in the window. Worker-measured, from the first step to the last.
- **Mean run time**: arithmetic mean of `duration_ms` of finished executions created in
  the window, measured by the control plane from the execution's start (or creation)
  to its terminal state, so it includes queueing between jobs.
- **Per-scenario average** (Quality → Health table): mean of that scenario's final
  attempts in the window.

## Flakiness

<a id="flakiness"></a>

A scenario is **flaky** in the window when either holds:

1. **Passed on retry**: in at least one execution an attempt failed, errored or timed
   out and a later attempt of the same scenario in the same execution passed.
2. **Flipped**: across its consecutive final runs (ordered by `finished_at`) the outcome
   changed between pass and not-pass at least twice.

Only runs finished after the scenario's last edit count, so fixing a test resets its
history.

```
flips      = number of consecutive final-run pairs whose outcome differs
flakiness  = flips / (runs - 1)    when runs > 2
           = 1.0                   when runs ≤ 2 (a scenario qualifies with ≤ 2 runs only by passing on retry)
```

The flaky list is ordered by flakiness, then by number of runs.

## Requirement coverage

<a id="coverage"></a>

A requirement is linked to scenarios explicitly (Projects → Requirements) or by tag: a
scenario tag equal to the requirement key (for example `@US-4`) links it when the suite
is saved.

- **Covered**: the requirement has at least one linked scenario that is approved and
  executable.
- **Verified**: covered, and the latest final run of *every* linked approved, executable
  scenario passed.
- **Failing**: at least one linked approved, executable scenario's latest final run
  failed, errored or timed out.
- **Never run** (per requirement): linked approved, executable scenarios with no
  finished run.

```
coverage_rate = covered  / requirements
verified_rate = verified / requirements
```

Both are `null` when the project has no requirements. Draft or deprecated scenarios and
scenarios with unsupported steps do not cover anything.

## Trends

Per calendar day (UTC) of the window:

- `executions`: executions created that day.
- `passed`, `failed`, `errored`: final attempts finished that day by outcome.
- `avg_duration_ms`: mean duration of those final attempts.

Days with no activity are present with zeros so the axis is continuous. The chart is
not drawn when every day is zero.

## Regression selection

Not a metric, but a score shown next to each selected scenario
([`crates/oryn-intelligence/src/regression.rs`](../crates/oryn-intelligence/src/regression.rs)):

| Signal | Score |
| --- | --- |
| The scenario exercises a route defined in a changed file | +3 |
| A keyword from a changed path (file stem or parent directory, ≥ 4 letters, not a stop word) appears in the scenario's name, suite, tags or steps | +2 |
| Either of the above, and the scenario failed on its last run | +1 |
| Either of the above, and the scenario is flaky | +1 |
| No other signal, and the scenario is tagged `@smoke` | 0.5 (baseline) |

Scenarios scoring 0 are not selected. Every selection lists the reasons that produced
its score.

## Recommendations

Generated by deterministic rules from the facts above (same file): uncovered
requirements, covered-but-unverified requirements, flaky scenarios, scenarios failing two
or more runs in a row, slow scenarios (average duration), approved scenarios that never
ran, and detected routes no scenario exercises. Refreshing replaces the rule-generated
recommendations; dismissed ones stay dismissed.

## AI usage

Settings → AI models reports per workspace: number of model requests, input and output
tokens and cost. Cost is `input_tokens × input_price + output_tokens × output_price`
(prices per million tokens, configured per model). Requests that failed are recorded
with zero tokens and their error. Usage figures are what providers reported, not
estimates.
