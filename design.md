# Design: ORYN

The locked system. Every screen reads this first and every screen shares it. Change it on purpose; this file is the rule.

## System

- Genre: modern-minimal (an engineering tool, app scope)
- Shape: app screen (top bar + section sidebar, dense tables, evidence views)
- Theme: Dose (by request, studied from `usehallmark.com/themes/dose`), translated from a household medication app into a quality-engineering workbench
- Axes: light (with an opt-in dark mode) / grotesk-sans / chromatic-green, posture committed
- Source of truth for values: `apps/web/styles/tokens.css` (generated by the Hallmark scaffold, `--scope app`)

## Philosophy

Dose is trustworthy because it is exact and unhurried: warm paper, green-black ink, a pharmacy label that states the dose, the time and who gave it. ORYN keeps that temperament and changes the subject. A test run is a dose record: **what ran, when, where, and what the evidence says.**

- **Evidence over assertion.** Every status on screen is backed by something you can open: a step, a log line, a screenshot. The UI never shows a verdict without its source.
- **AI is annotation, never the record.** Observations are set in ink on paper; AI interpretation is set on a tinted surface, labelled as interpretation, with its confidence.
- **Calm density.** Tables before cards, figures in tabular numerals, one accent doing every signal. The tool disappears into the work.
- **The signature object is the evidence label:** the DM Mono "pharmacy label" of a run or step (time, duration, worker, verdict), with a double-ringed stamp when assertions verified it.

What we took from Dose: warm paper, green-black ink, Schibsted Grotesk over Instrument Sans with DM Mono for times and identifiers, translucent plastic tints as *identity* colours, moulded controls, 10/14px radii, the label-and-stamp device.
What we left: the pill organiser, the window-light hero, the household voice, phone screens, the marketing layout. ORYN has no marketing page inside the app.

## Colour tokens

All colours come from `tokens.css`. No literal colour appears in component code; Tailwind utilities map to tokens (`bg-paper`, `text-ink`, `border-rule`).

| Token | Role |
|---|---|
| `--color-paper` | App ground (warm off-white) |
| `--color-paper-2` | Second neutral: sidebar, toolbars, table header band, code wells |
| `--color-paper-3` | Hover / selected row surface, sunken trays |
| `--color-ink` | Primary text, headings, ink band |
| `--color-ink-2` | Secondary text |
| `--color-muted` | Tertiary text, captions, placeholders, neutral states (queued, skipped, cancelled) |
| `--color-rule` | Hairlines, input borders at rest, table rules |
| `--color-accent` | Primary action, current selection, *passed / verified* |
| `--color-accent-deep` | Primary pressed / rim |
| `--color-accent-soft` | Checked keys, "verified" fills, success backgrounds |
| `--color-accent-ink` | Text on accent |
| `--color-focus` | Focus ring |
| `--color-error` | *Failed* and destructive confirmation only (see Variants) |
| `--p-mon … --p-sun` | Plastic identity tints. Used for test-kind lanes and project identity, never for state |

Rules: the accent marks the primary action, the current selection and the passed state, nothing else. A plastic tint never carries meaning about success or failure.

### Dark mode

Light is the default. Each person can pick **System**, **Light** or **Dark** in Settings → Appearance. The choice is stored in this browser (`oryn.prefs`) and set as `data-theme` on `<html>` before first paint (`lib/theme-boot.ts`). System follows `prefers-color-scheme`.

`apps/web/styles/theme-dark.css` re-lights the same tokens: green-black paper, warm paper-white ink, a lighter green accent with dark text on it, and a lighter red that is still the only failure colour. `--white` is the raised-surface token (panels, fields, menus, dialogs), so it turns dark too. Text that sits on a solid error fill uses `--color-paper`. Never write a colour that only works in one mode. The Monaco `oryn-paper` theme re-reads the tokens when the mode changes.

## Typography

| Role | Face | Size / weight |
|---|---|---|
| Page title (h1) | Schibsted Grotesk 700, tracking -0.03em, lh 1.05 | `--text-display` (1.728rem) |
| Section title (h2) | Schibsted Grotesk 700 | `--text-section` (1.2rem) |
| Card / panel title (h3) | Schibsted Grotesk 700 | `--text-title` (1rem) |
| Body | Instrument Sans 400/500 | 14px in dense tables, 16px in prose and forms |
| Labels, table heads, captions | Instrument Sans 500, one step smaller, sentence case, never tracked capitals | `--text-sm` / `--text-xs` |
| Times, durations, IDs, code, step text, HTTP methods | DM Mono 400/500, tabular numerals | text size |

Fixed app scale (ratio 1.2), no fluid headings. Three weights per screen at most (400, 500, 700). Figures are always `tabular-nums`. Mono is never used for nav, buttons, or table heads.

## Spacing

The scaffold scale: `2, 4, 8, 12, 16, 24, 40, 64, 96, 144` px (`--space-3xs` … `--space-4xl`). In Tailwind: `p-1` (4), `p-2` (8), `p-3` (12), `p-4` (16), `p-6` (24), `p-10` (40), `p-16` (64). Dense UI lives on 8/12/16; page sections separate on 24/40.

## Layout

- **Shell:** a 56px top bar (wordmark, workspace switcher, user menu) and a 232px sidebar on `--color-paper-2` holding the nine destinations (Overview, Projects, Test Studio, AI Test Planner, Executions, Quality Intelligence, Workers, Integrations, Settings). Nine destinations earn the sidebar. Under 60rem it collapses into a menu button in the top bar.
- **Content:** max width `--container` (1440px), gutter 24px (16px on phones). Page header = h1 + one line of description + at most one primary action, left-aligned.
- **Detail screens:** a main column with a 320px aside for metadata (the label) at ≥ 72rem; aside stacks above content below.
- State lives in the URL: tabs, filters, pagination, selected run.

## Surfaces

- **Paper** is the ground, flat (no grain in the app; grain is decorative and costs legibility in dense views).
- **Panel:** `--color-paper` or white-on-paper (`--light`) with a 1px `--color-rule` border and `--radius-card` (14px). Panels never nest inside panels; inner grouping uses rules and spacing.
- **Plastic:** a translucent tint band (62% alpha, glint top edge) used sparingly for identity: the test-kind strip on a suite, the project chip. One plastic element per view region.
- **Ink band:** one green-black band may carry a statement (e.g. the verdict summary of a run).
- **Label:** the evidence label (see Signature) is grained-free white paper, 10px radius, DM Mono throughout, a dashed tear-off rule above its foot.
- Shadows: `--shadow-lift` only on popovers, menus and dialogs. Panels sit flat with a border.

## Borders and radii

Hairline 1px `--color-rule`. Radii: 10px controls and inputs (`--radius-input`), 14px panels and dialogs (`--radius-card`), 999px tags and status pills. One radius per nesting level.

## Buttons

Moulded plastic, one size family in the app: 36px default height (40px for page-header actions), 44px hit target.

- **Primary:** green plastic: `--color-accent` → `--color-accent-deep` vertical fill, `--color-accent-ink` text, 1px deep rim and a 2px rim below, sinks 2px on `:active`. One filled primary per screen (dialogs count as their own screen).
- **Secondary:** clear plastic: white fill, glint inset, 1px `--color-rule` rim, 2px rule rim below.
- **Ghost:** text only, `--color-ink-2`, background `--color-paper-3` on hover.
- **Destructive:** secondary style with `--color-error` text; the confirmation dialog's button is filled `--color-error`.
- Eight states: rest, hover, focus-visible (2px `--color-focus` outline, offset 2px, instant), active (translateY 2px), disabled (opacity 0.55, `cursor: not-allowed`, native attribute), loading (spinner replaces icon, label kept, `aria-busy`), selected (for toggles: `--color-accent-soft` fill), error (for inline confirmation).

## Inputs

36px height, 10px radius, 1px `--color-muted` border at rest (constant width), white fill, focus is an inset outline not a border change, helper/error text reserved below at `min-height: 1lh`. Every field has a `<label>`; mobile font size 16px. Selects match inputs. Code inputs (Gherkin, JSON) use Monaco with a paper theme (`oryn-paper`) whose colours are derived from these tokens.

## Tables

The default way to show collections. Full width, no outer border, sentence-case heads on `--color-paper-2` that never wrap, horizontal 1px rules only, row height 44px, hover `--color-paper-3`. Numbers right-aligned in tabular numerals; times and IDs in DM Mono. When the table's own column is under 40rem (a container query, so phones and narrow panes alike) each row restacks as a labelled block; the row's name and its action stay visible.

## Navigation

Sidebar links: Instrument Sans 500, `--color-ink-2`; current page `--color-ink` on `--color-paper-3` with a 2px accent bar at the inline-start edge. One weight across states. Tabs inside screens: underline tabs, current tab ink with a 2px accent underline; tab rows scroll sideways rather than wrap. Breadcrumbs on detail screens.

## Status indicators

A status is a **pill with a glyph and a word**, never a dot alone, never colour alone.

| Status | Glyph | Treatment |
|---|---|---|
| passed / verified / online | check | `--color-accent-soft` fill, `--color-accent-deep` text |
| failed / error | x | `--color-error` at 12% fill, `--color-error` text |
| running / claimed | spinner (static ring under reduced motion) | `--color-paper-3` fill, ink text |
| queued / pending / draft | clock | transparent fill, `--color-rule` border, muted text |
| skipped / cancelled / offline / revoked | minus | transparent fill, muted text |
| flaky | wave | `--color-paper-3` fill, ink text, the word "flaky" |

AI-sourced items carry a "AI interpretation" tag with the confidence as a figure.

## Data visualisation

Recharts, only for measured series. Pass rate and execution counts over time: lines/bars in `--color-accent` (passed) and `--color-error` (failed), muted for others, 1px `--color-rule` gridlines on y only, axis text `--text-xs` muted, tabular numbers. No chart is drawn without data: an empty series shows the empty state. Every metric links to its documented calculation (`docs/METRICS.md`). Stats are a figure and a label, no icon tiles, no invented trend arrows.

## Signature: the evidence label

```
┌──────────────────────────────┐
│ Run 7f3a2c         Chromium  │
│ Checkout total               │
│ 14:02:11          2.41 s     │
│ - - - - - - - - - - - - - -  │
│ (( Verified 14:02:13 ))      │  ← double-ringed stamp, rotated 2deg
│   by worker local-01         │
└──────────────────────────────┘
```

Shown on execution detail and step detail. A failed run gets the same label with an unstamped grey "Not verified" ring and the failing assertion. The stamp only appears when the Rust engine validated assertions; an LLM can never produce it.

## Motion

Character: brisk and still. `--dur-micro` (120ms) for hover/press, `--dur-short` (220ms) for disclosure and popovers, `transform` and `opacity` only, never `transition: all`. The stamp lands once (scale 1.04 → 1, 220ms) when a run completes while you watch. Running status rings spin; under `prefers-reduced-motion` everything ends at once and spinners become static rings.

## Responsive

Breakpoints: 40rem (phone), 60rem (sidebar collapses), 72rem (detail aside docks). Body never under 16px on phones for inputs; tables restack; page-header actions wrap under the title. `overflow-x: clip` on html and body.

## Accessibility

WCAG 2.2 AA. Text contrast ≥ 4.5:1 (ink on paper ≈ 15:1; muted on paper ≈ 5.3:1). Every interactive element has an instant `:focus-visible` ring. Status never relies on colour alone (glyph + word). Live execution updates announce through an `aria-live="polite"` region. Dialogs trap focus and restore it. Hit targets ≥ 44px.

## Empty, loading and error states

Every region that loads data draws four states:

- **Loading:** a skeleton in the shape of the content (rows of the table, not a centred spinner).
- **Empty:** one sentence saying what belongs here and the one action that fills it ("No executions yet. Run a suite from Test Studio.").
- **Error:** what broke, the server message in mono, and a retry action.
- **Full.**

## Voice

Plain, exact, unhurried. Name the thing, the time, the place, who ran it. "Checkout total failed on Chromium at 14:02." Never "Oops", never exclamation marks, never a journey.

## Do-nots

- No purple or blue-to-purple gradients, no gradient fills beyond the button's moulded fill.
- No KPI card walls, no icon tiles, no decorative status dots, no emoji.
- No tracked capitals or eyebrows; labels are sentence case.
- No card inside a card.
- No invented numbers: every figure comes from the API.
- A plastic tint never signals state.

## Variants

- **Failure is red, not grey.** Dose renders a missed dose grey. In a quality tool a failed assertion is a defect signal engineers scan for, so `--color-error` marks *failed* (and only failed and destructive confirmation). Neutral states (skipped, cancelled, queued) remain grey as in Dose.
- **No paper grain or window light in the app.** Dense, legible tables come first.

## Exports

- `apps/web/styles/tokens.css` (source of truth) and `base.css` (Floor rules).
- Tailwind v4 mapping: `apps/web/app/globals.css` `@theme` block maps every token to utilities.
- shadcn variable mapping per Hallmark `export-formats.md` (Hallmark's `accent`/`muted` stay out of shadcn's names; shadcn primitives read `--primary` = `--color-accent`).
